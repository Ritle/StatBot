# Telegram Activity Bot

Асинхронный Telegram-бот на aiogram 3 для регистрации публикаций канала и активности
пользователей в связанной группе обсуждений. Данные хранятся в PostgreSQL через
SQLAlchemy AsyncIO; схема управляется Alembic.

На текущем этапе реализованы:

- безопасная настройка пары «канал — группа обсуждений» командой `/setup`;
- проверка прав администратора через Telegram Bot API и `SUPERADMIN_IDS`;
- диагностика конфигурации командой `/status`;
- идемпотентная регистрация публикаций и их автоматических копий в обсуждении;
- сбор обычных и медиа-комментариев, включая ответы другим пользователям;
- обновление профиля пользователя по стабильному Telegram user ID;
- хранение только длины и SHA-256 нормализованного текста, без полного текста комментария.

## Подготовка бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather), выполните `/newbot`, задайте имя и
   username, затем сохраните полученный токен в `BOT_TOKEN`.
2. В BotFather выполните `/setprivacy`, выберите бота и нажмите `Disable`. Иначе бот
   не будет получать все обычные сообщения группы.
3. В настройках канала создайте или выберите группу обсуждений и свяжите её с каналом.
4. Добавьте бота администратором канала. Дайте право публикации сообщений: оно также
   позволяет `/status` однозначно подтвердить рабочую конфигурацию.
5. Добавьте бота администратором связанной группы обсуждений. Это гарантирует получение
   сообщений независимо от Privacy Mode; отключить Privacy Mode всё равно рекомендуется.

Команды настройки доступны администраторам соответствующего канала и пользователям из
`SUPERADMIN_IDS`. Права пользователя и бота запрашиваются у Telegram при каждой
административной операции и не кэшируются надолго.

## `/setup`

Самый простой способ — выполнить `/setup` в связанной группе обсуждений. Бот получит
`linked_chat_id`, проверит обратную связь с каналом, права пользователя и права бота,
после чего сохранит Telegram ID обоих чатов в `channels`.

Из личного чата доступны два безопасных варианта:

```text
/setup -1001234567890
```

или `/setup`, после чего нужно переслать сообщение из канала. Если Telegram скрыл
источник пересылки, используйте числовой ID. Username не считается идентификатором и
не используется для доверенных связей. Узнать ID можно через служебного бота или из
Bot API update; ID каналов и супергрупп обычно начинается с `-100`.

Запуск `/setup` непосредственно от имени канала не используется: у `channel_post` нет
надёжного Telegram user ID администратора. Запускайте команду в группе обсуждений или
личном чате.

Если связь чатов корректна, конфигурация сохраняется даже при недостаточных правах
самого бота, а ответ явно перечисляет, что нужно исправить. Без подтверждённых прав
пользователя конфигурация не сохраняется.

## `/status`

Выполните `/status` в настроенной группе обсуждений. В личном чате передайте ID:

```text
/status -1001234567890
```

Команда показывает канал, группу, актуальные права бота, наличие активного периода,
число публикаций и комментариев, время последнего события и предупреждения.

Если комментарии не появляются:

- проверьте `/status` и устраните предупреждения о правах;
- убедитесь, что группа действительно назначена discussion group этого канала;
- отключите Privacy Mode и заново добавьте бота в группу, если Telegram не применил
  изменение к существующему членству;
- проверьте, что бот запущен и получает update типа `message` и `channel_post`;
- создайте новый пост после подключения и оставьте комментарий под ним.

## Как связываются публикации и комментарии

Telegram создаёт в discussion group автоматическую пересылку каждого поста. Она
содержит исходный ID публикации и собственный message ID в группе. Бот сохраняет эту
пару, а затем связывает с публикацией прямые ответы на корневое сообщение и ответы на
ранее сохранённые комментарии.

Повторная доставка update безопасна: база имеет уникальные ограничения для публикаций
и комментариев, а запись выполняется через PostgreSQL upsert в одной транзакции.
Сообщения из неизвестных групп, служебные события, сообщения ботов и сообщения от
имени канала/анонимного администратора не попадают в персональный рейтинг. Медиа без
caption сохраняется с длиной `0`.

Полная история до установки бота не восстанавливается: стандартный Bot API не выдаёт
боту архив всех старых постов, комментариев и промежуточных событий. Созданная после
подключения активность собирается с момента получения update.

## Ограничение удаления сообщений

Стандартный Telegram Bot API не отправляет надёжное событие удаления обычного сообщения
в группе. Поэтому бот не заявляет автоматическое обнаружение всех удалений. Репозиторий
сервис содержит административный метод `mark_comment_deleted`, который через репозиторий
помечает известный комментарий
удалённым и исключает его из подсчёта, если удаление подтверждено внешним процессом или
администратором.

## Периоды рейтинга

Для каждого канала периоды создаются и управляются независимо. Одновременно у канала
может быть только один период со статусом `active`; старые периоды сохраняются со
статусом `finished` или `cancelled` и физически не удаляются.

Административные команды:

- `/create_season` — пошагово создать черновик: название, локальные даты, баллы,
  дневной лимит и минимальная длина;
- `/start_season` — активировать выбранный черновик;
- `/finish_season` — после подтверждения рассчитать позиции и сохранить неизменяемый
  снимок в `season_results`;
- `/cancel_season` — отменить черновик или активный период без удаления данных;
- `/seasons` — показать архив с ID периодов;
- `/period` — показать настройки активного периода;
- `/recalculate` — после подтверждения заново вычислить активный рейтинг из исходных
  событий. Завершённые периоды эта команда не изменяет.

В FSM даты вводятся как `ДД.ММ.ГГГГ ЧЧ:ММ` в часовом поясе канала, а в PostgreSQL
сохраняются в UTC. Несуществующее время при весеннем переводе часов и неоднозначное
время при осеннем переводе отклоняются — администратор должен выбрать однозначный
момент. Кнопка подтверждения содержит одноразовый токен, поэтому старый callback не
создаст другой период.

## Правила начисления

Формула:

```text
score = counted_comments × comment_points + reactions × reaction_points
```

`total_comments` включает неудалённые комментарии обычных пользователей внутри границ
периода `[starts_at, ends_at)`, если пользователь не исключён для этого канала.
`counted_comments` дополнительно требует `is_countable = true`, минимальную длину и
попадание в дневной лимит. Лимит выбирает первые подходящие по длине комментарии
пользователя за локальный календарный день канала. PostgreSQL переводит каждый момент
из UTC по IANA timezone канала, поэтому дни корректны при летнем и зимнем времени.

Активные дни — число разных локальных дат, в которые был хотя бы один зачтённый
комментарий или учитываемая реакция. Боты, исключённые пользователи, удалённые
комментарии и активность другого канала не участвуют.

### Реакции на границах периода

Для активного периода применяется последовательная модель «добавлена внутри и активна
в момент расчёта»:

- реакция, добавленная в `[starts_at, ends_at)` и не снятая к моменту расчёта,
  учитывается;
- реакция, добавленная до начала периода и остающаяся активной, не учитывается;
- снятая до расчёта реакция не учитывается, даже если снятие произошло после
  `ends_at`;
- замена удаляет старую реакцию и создаёт новую с моментом замены; замена после конца
  периода поэтому не относится к нему;
- после `/finish_season` используются только строки `season_results`: последующие
  снятия и замены не меняют зафиксированный рейтинг.

Telegram update реакции сначала идемпотентно записывается в `reaction_events`, после
чего в той же транзакции обновляется множество `current_reactions`.

## Рейтинг и личная статистика

- `/rating` — общий рейтинг, по 10 участников на страницу;
- `/me` — место, баллы, фактические и зачтённые комментарии, реакции и активные дни;
- `/top_comments` — сортировка по зачтённым комментариям;
- `/top_reactions` — сортировка по реакциям.

У `/rating` есть кнопки «назад», «вперёд», «обновить» и «моё место». Завершённый архив
открывается командой `/rating ID_ПЕРИОДА`; ID показывает `/seasons`.

Основная сортировка детерминирована: баллы, зачтённые комментарии, реакции, активные
дни, более ранняя первая активность и меньший Telegram user ID. Агрегация, дневной
`row_number()` и итоговая позиция выполняются одним SQL-запросом без N+1.

В discussion group канал определяется автоматически. В личном чате бот проверяет
доступные пользователю настроенные группы: единственный канал выбирается сразу,
несколько показываются inline-кнопками, а при отсутствии доступных каналов выводится
понятная ошибка.

## Административное меню, исключения и экспорт

`/settings` открывает защищённое inline-меню канала: подключение, текущий период,
архив периодов, правила начисления, исключённые пользователи, CSV-экспорт и
диагностику. При каждом callback бот заново проверяет существование канала и
актуальные права администратора; одноразовые подтверждения и FSM-сценарии имеют
срок действия.

Правила черновика меняются сразу. Изменение правил активного периода требует
отдельного подтверждения, потому что немедленно влияет на текущий рейтинг.
Правила завершённого периода через обычное меню не меняются: для этого нужна
отдельная процедура пересчёта с явным изменением зафиксированных результатов.

- `/exclude` принимает reply, Telegram user ID или известный боту `@username`;
- `/include` возвращает пользователя в расчёт, не удаляя его профиль и активность;
- поиск username выполняется только по локальной базе, а неоднозначный результат
  требует выбора конкретного профиля;
- исключение влияет на последующие расчёты активного периода, но завершённые
  строки `season_results` автоматически не изменяются;
- `/export` предлагает активные и завершённые периоды. Активный период считается
  сервисом рейтинга, завершённый выгружается из `season_results`.

CSV записывается с UTF-8 BOM, стандартным экранированием полей и безопасным именем
с датами периода. Временный файл удаляется после отправки, а его формирование и
удаление вынесены из event loop. Успешные привилегированные действия сохраняются
в структурированном журнале `admin_audit_log`; токены, строки подключения и другие
секреты в метаданные не записываются.

## Конфигурация

Скопируйте пример и заполните секреты:

```bash
cp .env.example .env
```

```env
BOT_TOKEN=token_from_botfather
POSTGRES_PASSWORD=replace_with_url_safe_password
DATABASE_URL=postgresql+asyncpg://postgres:replace_with_url_safe_password@localhost:5432/activity_bot
TEST_DATABASE_URL=postgresql+asyncpg://postgres:replace_with_url_safe_password@localhost:5432/activity_bot_test
SUPERADMIN_IDS=123456789,987654321
LOG_LEVEL=INFO
DEFAULT_TIMEZONE=Europe/Amsterdam
BOT_MODE=polling
```

`TEST_DATABASE_URL` обязан указывать на отдельную базу с именем, оканчивающимся на
`_test`: integration-фикстура выполняет полный downgrade/upgrade и очищает таблицы.

## Требования и первый запуск

Для запуска без Docker нужны Python 3.12 и PostgreSQL 16. Создайте отдельные базы
`activity_bot` и `activity_bot_test`, скопируйте `.env.example` в `.env`, задайте
токен и URL-safe пароль PostgreSQL, затем выполните:

```bash
python -m pip install -e ".[dev]"
alembic upgrade head
python -m app.main
```

Для Docker нужны Docker Engine с Compose v2. В `.env` обязательны как минимум
`BOT_TOKEN` и `POSTGRES_PASSWORD`. Сервис `migrate` ждёт готовности PostgreSQL и
выполняет `alembic upgrade head`; `bot` запускается только после успешных миграций.
Runtime-образ работает от системного пользователя `bot`, не содержит тестов и
dev-зависимостей, использует read-only filesystem и отдельный tmpfs для временных
CSV. Readiness контейнера проверяет соединение с БД командой
`python -m app.healthcheck`.

После первого запуска:

1. проверьте `docker compose ps` и логи `docker compose logs migrate bot`;
2. выполните `/setup` в discussion group или передайте числовой ID в личном чате;
3. выполните `/status` и устраните все предупреждения;
4. создайте черновик периода через `/create_season`, затем запустите его;
5. опубликуйте новый пост и оставьте тестовый комментарий;
6. проверьте `/rating`, `/me` и CSV через `/export`.

## Команды

- `/setup`, `/status`, `/settings` — подключение, диагностика и меню администратора;
- `/create_season`, `/start_season`, `/finish_season`, `/cancel_season` — жизненный
  цикл периода;
- `/seasons`, `/period`, `/recalculate` — архив, текущие настройки и пересчёт;
- `/rating`, `/me`, `/top_comments`, `/top_reactions` — публичная статистика;
- `/exclude`, `/include` — исключение и возврат известного пользователя;
- `/export` — выбор периода и выгрузка CSV с UTF-8 BOM.

Экспорт экранирует CSV стандартным модулем Python и добавляет апостроф к профильным
полям, начинающимся с `=`, `+`, `-` или `@`, чтобы Excel не выполнял их как формулы.

## Ограничения Telegram

- Bot API не восстанавливает историю до подключения: учитываются только updates,
  полученные после запуска и настройки бота.
- Bot API не сообщает надёжно об удалении обычных сообщений в группе; без отдельного
  подтверждённого административного процесса такое удаление не меняет рейтинг.
- Анонимные реакции приходят как агрегированный `message_reaction_count` без Telegram
  user ID. Они намеренно не запрашиваются в `allowed_updates` и не участвуют в
  персональном рейтинге. Реакции от имени чата также игнорируются.
- Сообщения от имени канала, анонимных администраторов и других ботов не считаются
  персональной активностью.
- Реализован polling одного экземпляра бота. Webhook mode пока не реализован; два
  polling-экземпляра с одним токеном запускать нельзя.
- Редактирование старого комментария не пересчитывает сохранённую длину автоматически.

## Миграции и безопасность данных

Перед обычным запуском без Docker всегда выполняйте `alembic upgrade head`. В Docker
это делает одноразовый сервис `migrate`. Не запускайте несколько миграционных задач
параллельно и сначала делайте резервную копию перед обновлением production.

Завершённые результаты и журнал административных действий защищены внешними ключами
`RESTRICT`: удалить родительский период или канал случайным `DELETE` нельзя. `CASCADE`
оставлен только для зависимых событий внутри удаляемого агрегата; приложение не имеет
публичных команд удаления каналов, публикаций, периодов, пользователей или активности.
Downgrade миграции к 32-битным агрегатам завершится ошибкой, если production-значение
уже не помещается в `integer`, вместо молчаливого усечения данных.

## Резервное копирование PostgreSQL

Пример backup Docker-базы в custom format:

```bash
docker compose exec -T db pg_dump -U postgres -d activity_bot -Fc > activity_bot.dump
```

Проверяйте, что файл создан и не пуст. Для восстановления сначала остановите бота,
создайте отдельную пустую базу и восстановите dump туда; не проверяйте restore впервые
на production:

```bash
docker compose stop bot
docker compose exec -T db createdb -U postgres activity_bot_restore
docker compose exec -T db pg_restore -U postgres -d activity_bot_restore --exit-on-error < activity_bot.dump
```

После проверки можно переключить `DATABASE_URL` на восстановленную базу и снова
запустить `docker compose up -d`. Храните backup вне Docker volume и проверяйте
восстановление регулярно.

```bash
git pull --ff-only
```

Перед обновлением сделайте backup. Если `migrate` завершился с ошибкой, бот не

## Производительность и надёжность

Рейтинг рассчитывается одним SQL-запросом: фильтрация периода, локальные календарные
дни, дневной `row_number()`, итоговая сортировка и пагинация выполняются PostgreSQL.
Основные пути покрыты индексами `comments(channel_id, created_at)`,
`current_reactions(channel_id, created_at)` и уникальными индексами идентичности.
Полная выборка в Python используется только для явно запрошенного CSV-экспорта;
формирование файла вынесено из event loop.

Updates обрабатываются последовательно, чтобы комментарий не обогнал автоматическую
копию публикации, а реакции одного пользователя сохраняли порядок. Повторная доставка
безопасна благодаря upsert/unique constraints. Для Telegram 429 действует не более
двух повторов и только при ожидании до 30 секунд; подключение к PostgreSQL на startup
повторяется ограниченно. HTTP-запросы Telegram и SQL-команды имеют таймауты. При
SIGTERM polling останавливается, HTTP-сессия закрывается, пул PostgreSQL освобождается;
собственных бесконечных фоновых задач у приложения нет.

## Архитектура

```text
Telegram update
    → handler (только принимает update и открывает транзакцию)
    → mapper (aiogram Message → внутренняя структура)
    → service (определяет канал, публикацию и правила обработки)
    → repository (upsert/query)
    → PostgreSQL
```

Проверка прав вынесена в `app/services/permissions.py`, настройка — в
`app/services/channel_setup.py`, сбор событий — в `app/services/activity.py`.
Репозитории выполняют `flush`/upsert, но граница commit принадлежит handler/service
сценарию.
