# Telegram Activity Bot

Асинхронный Telegram-бот на aiogram 3 для регистрации публикаций канала и активности
пользователей в связанной группе обсуждений. Данные хранятся в PostgreSQL через
SQLAlchemy AsyncIO; схема управляется Alembic.

На текущем этапе реализованы:

- безопасная настройка пары «канал — группа обсуждений» командой `/setup`;
- проверка прав администратора через Telegram Bot API и `SUPERADMIN_IDS`;
- диагностика конфигурации командой `/status`;
- идемпотентная регистрация публикаций и их автоматических копий в обсуждении;
- сбор обычных и медиа-комментариев, включая ответы другим пользователям;
- обновление профиля пользователя по стабильному Telegram user ID;
- хранение только длины и SHA-256 нормализованного текста, без полного текста комментария.

## Подготовка бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather), выполните `/newbot`, задайте имя и
   username, затем сохраните полученный токен в `BOT_TOKEN`.
2. В BotFather выполните `/setprivacy`, выберите бота и нажмите `Disable`. Иначе бот
   не будет получать все обычные сообщения группы.
3. В настройках канала создайте или выберите группу обсуждений и свяжите её с каналом.
4. Добавьте бота администратором канала. Дайте право публикации сообщений: оно также
   позволяет `/status` однозначно подтвердить рабочую конфигурацию.
5. Добавьте бота администратором связанной группы обсуждений. Это гарантирует получение
   сообщений независимо от Privacy Mode; отключить Privacy Mode всё равно рекомендуется.

Команды настройки доступны администраторам соответствующего канала и пользователям из
`SUPERADMIN_IDS`. Права пользователя и бота запрашиваются у Telegram при каждой
административной операции и не кэшируются надолго.

## `/setup`

Самый простой способ — выполнить `/setup` в связанной группе обсуждений. Бот получит
`linked_chat_id`, проверит обратную связь с каналом, права пользователя и права бота,
после чего сохранит Telegram ID обоих чатов в `channels`.

Из личного чата доступны два безопасных варианта:

```text
/setup -1001234567890
```

или `/setup`, после чего нужно переслать сообщение из канала. Если Telegram скрыл
источник пересылки, используйте числовой ID. Username не считается идентификатором и
не используется для доверенных связей. Узнать ID можно через служебного бота или из
Bot API update; ID каналов и супергрупп обычно начинается с `-100`.

Запуск `/setup` непосредственно от имени канала не используется: у `channel_post` нет
надёжного Telegram user ID администратора. Запускайте команду в группе обсуждений или
личном чате.

Если связь чатов корректна, конфигурация сохраняется даже при недостаточных правах
самого бота, а ответ явно перечисляет, что нужно исправить. Без подтверждённых прав
пользователя конфигурация не сохраняется.

## `/status`

Выполните `/status` в настроенной группе обсуждений. В личном чате передайте ID:

```text
/status -1001234567890
```

Команда показывает канал, группу, актуальные права бота, наличие активного периода,
число публикаций и комментариев, время последнего события и предупреждения.

Если комментарии не появляются:

- проверьте `/status` и устраните предупреждения о правах;
- убедитесь, что группа действительно назначена discussion group этого канала;
- отключите Privacy Mode и заново добавьте бота в группу, если Telegram не применил
  изменение к существующему членству;
- проверьте, что бот запущен и получает update типа `message` и `channel_post`;
- создайте новый пост после подключения и оставьте комментарий под ним.

## Как связываются публикации и комментарии

Telegram создаёт в discussion group автоматическую пересылку каждого поста. Она
содержит исходный ID публикации и собственный message ID в группе. Бот сохраняет эту
пару, а затем связывает с публикацией прямые ответы на корневое сообщение и ответы на
ранее сохранённые комментарии.

Повторная доставка update безопасна: база имеет уникальные ограничения для публикаций
и комментариев, а запись выполняется через PostgreSQL upsert в одной транзакции.
Сообщения из неизвестных групп, служебные события, сообщения ботов и сообщения от
имени канала/анонимного администратора не попадают в персональный рейтинг. Медиа без
caption сохраняется с длиной `0`.

Полная история до установки бота не восстанавливается: стандартный Bot API не выдаёт
боту архив всех старых постов, комментариев и промежуточных событий. Созданная после
подключения активность собирается с момента получения update.

## Ограничение удаления сообщений

Стандартный Telegram Bot API не отправляет надёжное событие удаления обычного сообщения
в группе. Поэтому бот не заявляет автоматическое обнаружение всех удалений. Репозиторий
сервис содержит административный метод `mark_comment_deleted`, который через репозиторий
помечает известный комментарий
удалённым и исключает его из подсчёта, если удаление подтверждено внешним процессом или
администратором.

## Конфигурация

Скопируйте пример и заполните секреты:

```bash
cp .env.example .env
```

```env
BOT_TOKEN=token_from_botfather
DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/activity_bot
TEST_DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/activity_bot_test
SUPERADMIN_IDS=123456789,987654321
LOG_LEVEL=INFO
DEFAULT_TIMEZONE=Europe/Amsterdam
BOT_MODE=polling
```

`TEST_DATABASE_URL` обязан указывать на отдельную базу с именем, оканчивающимся на
`_test`: integration-фикстура выполняет полный downgrade/upgrade и очищает таблицы.

## Запуск и проверки

Нужны Python 3.12 и PostgreSQL:

```bash
python -m pip install -e ".[dev]"
alembic upgrade head
python -m app.main
```

Или через Docker Compose:

```bash
docker compose up --build
docker compose run --rm bot alembic upgrade head
```

Проверки качества:

```bash
pytest
ruff check .
mypy app tests
alembic check
```

## Архитектура

```text
Telegram update
    → handler (только принимает update и открывает транзакцию)
    → mapper (aiogram Message → внутренняя структура)
    → service (определяет канал, публикацию и правила обработки)
    → repository (upsert/query)
    → PostgreSQL
```

Проверка прав вынесена в `app/services/permissions.py`, настройка — в
`app/services/channel_setup.py`, сбор событий — в `app/services/activity.py`.
Репозитории выполняют `flush`/upsert, но граница commit принадлежит handler/service
сценарию.
